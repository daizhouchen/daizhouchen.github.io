01 / BUSINESS CONTEXT

买家需要的不止商品，
还有采购方案。

产品定位：连接海外中小买家与国内工厂的 B2B 跨境贸易平台。

找到商品之后，
还有规格、报价与交付需要对齐。

采购方要把需求表达清楚，工厂要判断能否承接，双方还要围绕报价与履约持续沟通。UniTrade 围绕这些任务设计采购协作流程，并梳理直采、拼单和 OEM 的不同采购入口。

01直采
已有明确商品需求

从商品与规格出发，连接供给、询价与交易跟进，让买家有路径推进下一步。

02拼单
围绕共同需求组织采购

把需求聚合与供给承接放在一起考虑，梳理参与、询价和后续履约的协作流程。

03OEM
先明确定制要求，再寻找工厂

围绕需求提交、供应商匹配与报价比较组织流程，让沟通有共同的需求依据。

02 / PROCUREMENT JOURNEY

围绕一笔采购，
设计角色与交接。

以下按产品方案说明采购路径，网页端交付与 Agent 内测分阶段推进。每个环节都要留下下一步可用的信息，也要明确谁来处理。

  1. 01

    需求提交

    整理采购意图与商品要求，形成可供检索、匹配和询价使用的需求。

    留下什么 / 结构化需求

  2. 02

    供需匹配

    结合商品、类目、属性与多语言信息，找到可继续沟通的商品和供应商。

    留下什么 / 候选供给

  3. 03

    询价与比较

    对接多方询价，汇总报价信息，帮助买家围绕同一采购需求比较方案。

    留下什么 / 报价与待确认事项

  4. 04

    确认与履约

    由人确认交易与付款，继续对接买家、工厂和渠道，跟进履约中的问题。

    留下什么 / 确认结果与跟进事项

我的业务参与：对接工厂、买家与渠道，参与匹配、报价和履约，再将实际交易问题整理为产品需求。

03 / AI IN THE WORKFLOW

让 AI 处理信息，
让人推进生意。

参与询盘、选品、上品与客服 Agent 研发。以下按内测方案说明任务分工与人工衔接。

Agent · 内测探索

围绕具体任务用 AI，
把输出接回采购流程。

已有自动化：商品与供应商资料的多语言处理

交易平台接入机器翻译服务，处理商品名称、描述、规格和供应商资料，用于多语言展示，并将商品译文纳入检索信息。围绕采购任务的四类 Agent 则在研发与内测中探索。

SUPPLY

上品 Agent

商品资料 → 可组织的商品信息

围绕资料解析、类目与属性标准化、多语言信息整理，支持供给接入与商品上架。

人工衔接 / 核对商品规格和供给信息，再用于发布与后续匹配。

MATCH

选品 Agent

采购需求 → 可继续询价的候选供给

将需求结构化，结合商品与需求检索组织供需匹配，让选品结果进入询价流程。

人工衔接 / 判断候选是否满足实际采购要求，确认后继续沟通。

INQUIRY

询盘 Agent

需求与候选 → 多方询价与报价汇总

设计询价和报价汇总流程，兼容真人与 Agent 的交互，让多方信息回到同一采购任务。

人工衔接 / 确认报价与交易条件，付款环节由人确认。

SERVICE

客服 Agent

业务咨询 → 人与 Agent 协同处理

参与客服 Agent 研发，探索咨询处理与真人协作，使交互能够衔接后续业务沟通。

人工衔接 / 涉及交易判断或需进一步确认的问题，进入人工沟通。

网页端上线与 Agent 内测属于不同阶段；上述任务分工是产品设计与内测探索范围。

04 / PRODUCT DECISIONS

业务规则，
决定 AI 怎么参与。

从采购协作倒推数据、交互与确认环节的设计。

01

先统一商品与需求的表达

商品资料、类目、属性和多语言信息共同构成检索基础。将这些信息用于商品上架、供应商匹配与 Agent 查询，让不同环节围绕同一套商品信息协作。

产品考虑 / 选品和询价都需要可比较的信息，数据整理应服务实际采购任务。

02

给真人与 Agent 留下共同入口

在询盘和报价协作中兼容真人与 Agent 交互，将需求、候选与报价作为不同参与方之间的交接内容。

产品考虑 / 业务参与方的协作方式不同，流程需要容纳人工沟通。

03

把付款确认留给人

Agent 参与需求整理、匹配和询价，交易与付款仍需人工确认。将信息处理与交易决策分开设计，明确每一步的责任。

产品考虑 / 报价与匹配结果是决策依据，最终确认需要回到实际交易方。
